# Брейнрот-рыбалка — каркас

Минимальный рабочий скелет режима: вход в зону → шкала силы → заброс →
определение зоны глубины → ролл добычи → выплата монет. Ферма, магазины и
погоня с акулой подключаются в те же точки (помечены `TODO`).

## Файлы

| Файл | Роль | Меняешь, когда |
|---|---|---|
| `brainrot_types.verse` | Каталог брейнротов, таблица зон, ролл редкости | добавляешь контент или крутишь баланс |
| `player_state.verse` | Сейв, монеты, сила, удочки | добавляешь новый параметр прогресса |
| `power_bar.verse` | UMG-шкала силы | меняешь вид или ощущение шкалы |
| `game_manager.verse` | Корневое устройство, вся логика петли | подключаешь новые этапы |

Зависимости строго в одну сторону: `game_manager` → всё остальное.
Файлы данных не знают друг о друге. Это единственное, что не даёт проекту
превратиться в кашу к третьему этапу.

## Установка в UEFN

1. **Новый проект** из шаблона **Blank**. Не Island Template — лишняя
   геометрия съест бюджет памяти, а выкинуть её потом сложнее, чем добавить.
2. **Verse Explorer** → правый клик по имени проекта → *Show in Explorer*.
   Скопируй четыре `.verse` файла в `<Проект>/Content/<ИмяПроекта>/`.
3. **Verse → Build Verse Code** (Ctrl+Shift+B). Должно собраться без ошибок.
   Если ругается на UMG — см. «Если не компилируется» ниже.
4. В **Content Browser** появится устройство `game_manager`. Перетащи его
   на карту. Один экземпляр, больше не нужно.
5. Расставь девайсы и пропиши их в Details у `game_manager`:

   | Поле | Девайс | Настройка |
   |---|---|---|
   | `CastZone` | Mutator Zone | Zone Width/Depth по зелёной зоне на пирсе |
   | `CastInput` | Input Trigger | Input Type: *Primary Fire*, Enabled on Start: **Off** |
   | `CatchHud` | HUD Message | Display Time 3s, позиция по центру снизу |
   | `CastSound` | Audio Player | звук всплеска |
   | `PerfectSound` | Audio Player | джингл идеального броска |

6. **Launch Session**. Зайди в зелёную зону — появится шкала. Жми огонь.

## Как это работает

**Одна петля на игрока.** `OnCastPressed` не может быть `<suspends>`
(подписки на события синхронные), поэтому она только запускает
`spawn{ FishingLoop(Player) }`. Дальше вся рыбалка живёт в своей корутине и
не мешает другим игрокам.

**Защёлка вместо очереди.** Одно и то же нажатие означает «начать» или
«остановить шкалу» в зависимости от `IsFishing`. Флаг `PressLatch` читается
и сбрасывается атомарно в `TakeLatch` — без этого быстрый двойной клик
съедает бросок.

**Сейв иммутабелен.** `<persistable>`-класс не может содержать `var`. Любое
изменение — это новый объект: `SetSave(P, WithCoins(Old, Old.Coins + 10))`.
Отсюда хелперы `With*`. Поле `Version` не удаляй — через него мигрируешь
структуру, когда добавишь новое поле, без вайпа игроков.

**Данные отдельно от логики.** Новый брейнрот — строчка в
`BrainrotCatalog`. Баланс — числа в `ZoneTable`. Ни то, ни другое не
требует трогать `game_manager`.

**Ролл в два шага.** Сначала выбирается *редкость* по весам зоны, потом
равновероятно берётся любой брейнрот этой редкости. Поэтому добавление
десяти новых Common не делает Common чаще — меняется только разнообразие.

## Проверка перед тем, как идти дальше

- [ ] Шкала появляется на входе в зону и исчезает на выходе
- [ ] Слабый бросок стабильно даёт зону 1, идеальный — максимум для удочки
- [ ] Двойной клик не ломает состояние, второй заброс не стартует поверх первого
- [ ] Монеты переживают выход и повторный вход в сессию
- [ ] Два игрока могут забрасывать одновременно, не влияя друг на друга

## Если не компилируется

UMG-неймспейсы в UEFN менялись между версиями чаще всего остального.
Если падает `power_bar.verse`:

- Проверь набор `using` вверху файла против любого рабочего UMG-примера
  из шаблонов UEFN твоей версии.
- `NamedColors.LimeGreen` может называться иначе — подставь
  `MakeColorFromHex("3ECB77")`.
- `player_ui_slot{ InputMode := ui_input_mode.None }` в старых версиях
  создаётся без параметров: `player_ui_slot{}`.

Логика в остальных трёх файлах от версии не зависит.
