# Девайсы и каркасы в UEFN — с нуля

Разбор того, из чего вообще состоит логика в UEFN: что такое девайс, чем
он отличается от твоего кода, и четыре способа их связать.

Рабочий пример целиком: `verse/examples/tower_device.verse`.

---

## 1. Ментальная модель

В UEFN есть ровно две вещи, из которых собирается вся логика.

**Девайс от Epic** — готовый кубик, который умеет одну вещь. Кнопка умеет
«на меня нажали». Зона умеет «в меня вошли». Таймер умеет «прошло N
секунд». У каждого есть настройки в панели **Details** и набор событий.

**Твоё устройство** — `class(creative_device)` на Verse. Снаружи выглядит
точно так же: его кладут на карту, у него есть Details. Но внутри —
твой код, который слушает чужие девайсы и дёргает их методы.

Дальше всё сводится к одному вопросу: **как твой код узнаёт про девайс на
карте и как он с ним разговаривает.**

---

## 2. Четыре способа связать

### Способ 0 · Прямая привязка, без кода

У многих девайсов в Details есть секция **Direct Event Binding** (иногда
подписана как Functions / Events). Выглядит так:

```
Trigger Device → Details → Direct Event Binding
  On Triggered  →  Select Device: [Item Granter]
                   Select Function: [Grant Item]
```

Всё. Нажали на триггер — выдался предмет, Verse не нужен.

**Когда хватает:** двери, лифты, выдача стартового набора, телепорты.
**Когда ломается:** как только логика зависит от состояния («выдать, если
монет больше 300»). Условий тут нет, только «событие → действие».

Не пренебрегай этим. Половина простых связок в хорошем режиме сделана
мышкой, и это нормально — код, которого нет, не падает.

### Способ 1 · `@editable` — ссылка из Verse на девайс

Это основной способ. Пишешь поле в классе:

```verse
@editable
MyButton : button_device = button_device{}
```

После компиляции у твоего устройства в Details появляется поле **MyButton**
с выпадающим списком всех кнопок на карте. Выбираешь мышкой нужную.

**Что справа от `=`.** Это не девайс. Это пустая заглушка, нужная только
чтобы поле имело тип и дефолт. Verse требует, чтобы поле было чем-то
инициализировано.

**Главная ошибка новичка:** скомпилировал, забыл выбрать девайс в Details,
запустил — ничего не работает, ошибок нет. Подписка ушла в заглушку,
которой нет на карте. Всегда проверяй Details после добавления `@editable`.

Работает и с массивами, и с числами:

```verse
@editable
Slots : []button_device = array{}      # список в Details

@editable
FireRate : float = 1.0                 # число, крутится без перекомпиляции
```

Числа выноси в `@editable` агрессивно. Каждая правка баланса без
пересборки Verse экономит минуту, а правок будут сотни.

### Способ 2 · `Subscribe` — подписка на событие

Ссылка есть, теперь надо услышать девайс:

```verse
OnBegin<override>()<suspends> : void =
    MyButton.InteractedWithEvent.Subscribe(OnPressed)

OnPressed(Agent : agent) : void =
    Print("нажали")
```

`InteractedWithEvent` — это `listenable(agent)`, «сюда можно подписать
функцию, которой я буду присылать agent».

**Три правила обработчика, которые нарушают все:**

1. Тип аргумента обязан совпадать с тем, что шлёт событие. Кнопка шлёт
   `agent` — значит `(Agent : agent)`, а не `(Player : player)`.
2. Обработчик **не может быть `<suspends>`**. Событие вызывает его
   синхронно и ждать не умеет. Нужно подождать внутри — `spawn`.
3. Подписываться надо в `OnBegin`, один раз. Подписка в цикле — это
   десять обработчиков на одно нажатие.

Подписка возвращает `cancelable`, если её надо потом снять:

```verse
Sub := MyButton.InteractedWithEvent.Subscribe(OnPressed)
# позже:
Sub.Cancel()
```

### Способ 3 · Вызов методов девайса

Обратное направление — ты приказываешь девайсу:

```verse
MyHud.SetText(SomeMessage())
MyHud.Show(Player)          # одному игроку
MySound.Play()              # всем
MyBarrier.Disable()
MyTimer.Start()
```

Полный список методов конкретного девайса — в API-референсе
`Fortnite.com/Devices`. Держи документацию открытой: имена методов у
похожих девайсов различаются (`Show`/`Display`, `Enable`/`Activate`), и
угадывать бесполезно.

## 3. Три сущности игрока, которые все путают

Это источник половины ошибок компиляции на старте.

| Тип | Что это | Откуда берётся |
|---|---|---|
| `agent` | «кто-то в игре» — игрок или NPC | приходит во всех событиях девайсов |
| `player` | именно человек, к нему привязан сейв | `player[Agent]` |
| `fort_character` | физическое тело на карте: урон, позиция, скорость | `Agent.GetFortCharacter[]` |

Оба перехода **failable** — в квадратных скобках, внутри `if`:

```verse
OnPressed(Agent : agent) : void =
    if (Player := player[Agent]):              # агент может быть NPC
        AddCoins(Player, 100)
    if (Character := Agent.GetFortCharacter[]): # тела может не быть: умер, вышел
        Character.Damage(25.0)
```

Почему failable, а не просто приведение: между событием и твоим кодом
игрок мог умереть или выйти. Verse заставляет это обработать, вместо того
чтобы уронить сессию.

## 4. Время: `OnBegin`, `spawn`, `loop`, `Sleep`

`OnBegin` вызывается один раз при старте, на **каждом** экземпляре
устройства на карте. Положил три башни — `OnBegin` отработает трижды, у
каждой свои поля и своё состояние.

`<suspends>` на функции означает «умею ждать». Такую функцию можно звать
только из другой `<suspends>` или через `spawn`.

```verse
OnBegin<override>()<suspends> : void =
    MyZone.AgentEntersEvent.Subscribe(OnEnter)
    spawn{ TickLoop() }        # параллельно, управление возвращается сразу

TickLoop()<suspends> : void =
    loop:
        Sleep(1.0)
        DoWork()
```

**Без `spawn` петля повесила бы `OnBegin` навсегда**, и подписки ниже
никогда бы не появились. Это ошибка номер один у начинающих.

Оператор `spawn` — мост из синхронного мира событий в асинхронный:

```verse
OnPressed(Agent : agent) : void =     # ждать нельзя
    if (Player := player[Agent]):
        spawn{ LongThing(Player) }    # а тут уже можно
```

Ещё четыре оператора, которые понадобятся позже:

- `race { A(); B() }` — что первым закончилось, то и победило, второе
  отменяется. Так делается таймаут: `race { Minigame(); Sleep(10.0) }`
- `sync { A(); B() }` — оба параллельно, ждём обоих
- `branch { A() }` — запустить и не ждать, но отменить вместе с родителем
- `rush { A(); B() }` — как race, но проигравший не отменяется

## 5. Каркас: как устроено твоё устройство

Скелет, который повторяется в любом `creative_device`:

```verse
my_device := class(creative_device):

    # 1. Ссылки на девайсы с карты
    @editable
    SomeButton : button_device = button_device{}

    # 2. Настройки, которые крутятся без перекомпиляции
    @editable
    SomeNumber : float = 1.0

    # 3. Рантайм-состояние
    var Counter : int = 0

    # 4. Подписки и запуск петель
    OnBegin<override>()<suspends> : void =
        SomeButton.InteractedWithEvent.Subscribe(OnPressed)
        spawn{ TickLoop() }

    # 5. Обработчики — синхронные, короткие
    OnPressed(Agent : agent) : void =
        set Counter += 1

    # 6. Петли — асинхронные, длинные
    TickLoop()<suspends> : void =
        loop:
            Sleep(1.0)
```

Этот порядок держи во всех файлах. Когда через месяц вернёшься к коду,
глаз будет искать подписки в одном и том же месте.

**Одно устройство — одна ответственность.** Башня знает про свою зону и
свою стрельбу. Она не знает, сколько башен на карте и кто ими управляет.
Если нужен общий счёт — заводи отдельный `game_manager`, который держит
массив `@editable []tower_device` и опрашивает их.

## 6. Частые грабли

**Подписка не сработала, ошибок нет.** В 90% случаев — девайс не выбран в
Details. Проверяй первым делом.

**«Обработчик не может быть suspends».** Убери `<suspends>`, оберни тело
в `spawn{ }`.

**Двойное срабатывание.** Подписался в цикле или в функции, которая
вызывается больше одного раза. Подписки живут только в `OnBegin`.

**Состояние течёт между игроками.** `var Counter : int` — один на всё
устройство. Нужно на каждого — `var Counters : [player]int = map{}`.

**Удаление из массива.** Его нет. Пересобирай массив без лишнего:
`for (X : Items, X <> Removed) { set Kept += array{X} }`.

**Сравнение агентов.** Работает через `=` и `<>`, но только для самих
`agent`/`player`, не для их персонажей.

**Девайсов на карте больше, чем кажется.** Каждый `creative_device` из
Content Browser — отдельный экземпляр со своим состоянием. Положил два
`game_manager` по невнимательности — получил две петли дохода и двойные
начисления.

## 7. Порядок обучения

1. Собери сцену **без единой строчки Verse**: кнопка → Direct Event
   Binding → выдача предмета. Пойми, что девайсы самодостаточны.
2. Сделай пустой `creative_device` с одним `Print` в `OnBegin`. Убедись,
   что видишь его в логе.
3. Добавь один `@editable button_device` и подписку. Нажми кнопку,
   получи `Print`.
4. Добавь `spawn{ }` с петлёй и `Sleep`. Почувствуй разницу между
   синхронным обработчиком и асинхронной петлёй.
5. Только теперь бери `verse/examples/tower_device.verse` — там всё это
   вместе плюс зона, урон и апгрейд за монеты.

Не прыгай сразу на шаг 5. Каждый из первых четырёх ловит свой класс
ошибок, и ловить их по одной сильно быстрее, чем все разом.
